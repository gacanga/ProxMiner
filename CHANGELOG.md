# Changelog

## 0.3.0 - 2026-10-30

- Field functions take and return values: operands stay in registers instead of local memory
  (was 16 loads + 8 stores per multiplication).
- Stage 1 is SHA-512 + a Jacobi-symbol test of the point equation (`fe_jacobi`, binary algorithm, no
  exponentiation); only the nonces whose hash is a curve point go to stage 2, which decodes them: no thread
  computes a square root for nothing.
- One shared inversion per 16 points (Montgomery's trick, `px_stage2_batch`).
- Stage 2 at 64 registers per thread (128 threads x 8 blocks per SM).
- NVIDIA P104-100, 30 s benchmark: 0.2.0 1 376 kH/s -> 0.3.0 2 025 kH/s (+47 %).
- Tests: Jacobi symbol against Euler's criterion (20 000 values), batched stage 2 against single-point
  stage 2 (batches of 1 to 16); `--test` GPU against the CPU reference unchanged.

## 0.2.0 - 2026-10-29

- GPU field arithmetic in inline PTX with carry chains (`gpu/fe_ptx.h`, generated by `tools/gen_fe_ptx.py`,
  checked by `tests/ptx_sim.py`), and `fe_mul` / `fe_sq` as real (non-inlined) functions on the GPU.
- NVIDIA P104-100, 30 s benchmark: 0.1.0 916 kH/s -> 0.2.0 1 376 kH/s (+50 %). Inlined PTX: 670 kH/s;
  C arithmetic as functions: 1 066 kH/s.
- Same work function, same protocol, same tests (`--test` GPU against the CPU reference).

## 0.1.0 - 2026-10-28

- First release: CUDA nonce seeker for `proxi node mine` (external nonce seeker protocol), work function
  ECVRF-EDWARDS25519-SHA512-TAI (RFC 9381) as the Proxima mine chain requires.
- Two-stage GPU engine (hash + point decoding, then wNAF(5) scalar multiplication), every candidate
  recomputed on the CPU, GPU self-check at start and every 10 minutes.
- Windows package with the Proxima node and wallet (`proxima.exe`, `proxi.exe`, v1.3.8p1, unmodified)
  and setup / start / stop scripts.
- Tests: RFC 9381 vectors, independent Python reference, CPU stand-in + fake job server.
